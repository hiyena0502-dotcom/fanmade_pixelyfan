# 화면 및 제작 기준

- 실제 게임 플레이에만 **3000 × 1440 (25:12)** 공통 제작 영역과 갈색 `#4A3529` CSS 여백을 적용한다. 영역 전체를 비율대로 축소하며 게임 내부의 기존 16:9 좌표와 클릭 영역을 보존한다.
- 홈, 옷장, 챕터, 콜렉션, 새 게임·이어하기 슬롯은 브라우저 전체를 사용한다. 홈의 배경·집·정원은 원본 비율 그대로 화면을 덮고 제목과 메뉴는 안전 영역에 배치한다. 원본 파일을 자르거나 늘이지 않는다.
- 설정·개발자 창, 옷장·책, 저장 슬롯은 화면에 맞는 별도 표시 배율을 사용한다. 일반 PC에서는 원래 UI의 약 118% 크기로 표시하고 작은 창에서는 사용 가능한 영역에 맞춰 줄인다. 게임 이미지·장착 파츠·저장 좌표에는 이 배율을 적용하지 않는다.
- 게임 대사도 같은 읽기 배율로 표시한다. 긴 대사는 실제 글자 높이로 나누므로 글씨 크기를 임의로 줄이거나 뒷부분을 누락하지 않는다. 사용자 글씨 크기 설정 자체는 유지한다.
- 모험 일기에서 지나온 기록·완료 목표 목록·발견 및 조사 횟수 표시를 제거한다. 현재 장소와 목표는 보여 주며 실제 진행·수집·조사 데이터는 보존한다.
- 게임 속 일기와 콜렉션은 현재 장소 위에 창으로 연다. 콜렉션을 닫아도 페이지 이동이나 장소 재생성이 발생하지 않는다. 메인 메뉴의 별도 콜렉션 화면은 그대로 유지한다.
- 새 게임·이어하기·불러오기 및 장소 이동은 필요한 배경·캐릭터·레이어와 옷장 모습을 준비한 뒤 표시한다. 장소 이동의 흰색 덮개 효과를 사용하지 않는다. 실패하면 현재 화면을 유지하고 재시도 안내를 표시한다. 이동 중에는 중복 입력을 막는다.
- 서버에 게시된 콘텐츠와 기존 브라우저 저장 데이터를 초기화하거나 기본 데이터로 덮어쓰지 않는다. 개발자 로그인·편집·업로드는 백업용으로 보존한다.

## 앞으로의 제작 방식

한 번에 요청받은 장면 또는 기능을 수정한다. 이미지·대사·옷장 파츠는 요청 없이 바꾸지 않는다. 다른 화면에 영향을 주면 범위를 먼저 설명한다. 확인한 코드를 GitHub `rebuild-v2`에 반영하고 기존 Vercel 주소에서 배포 결과를 확인한다.

## 이번 변경 파일과 영향

- `stage.js`, `stage.css`, 다섯 HTML: 플레이와 일반 메뉴의 표시 영역 분리, 가독성 배율, 갈색 여백.
- `game.js`, `game.css`, `scene-transition.js`: 일기 표시 정리, 이미지 준비 후 진입·이동, 현재 장소 위 콜렉션 창, 대사 측정 배율.
- `viewport-preview.js`: 준비된 플레이 화면을 기준으로 기존 개발자 비율 미리보기 배율을 갱신.
- `books.js`, `collection.html`: 팝업 안에서 배경 투명 처리 및 닫기 연결. 메인 메뉴에서 열면 기존 별도 화면으로 표시.
- `tests/stage.test.cjs`, `tests/scene-transition.test.cjs`: 배율·좌표 및 이미지 준비·중복 로딩·실패 후 재시도 검사.
- 이 문서: 현재 기준 정리. 검증용 로그인·대사·저장 데이터와 QA 페이지는 정식 브랜치에 포함하지 않는다.
