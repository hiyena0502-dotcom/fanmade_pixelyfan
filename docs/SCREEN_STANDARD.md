# 화면 및 제작 기준

- 공통 제작 영역: **3000 × 1440 (25:12)**. CSS와 `stage.js`에서 동일한 배율로 전체 영역을 브라우저에 맞춘다.
- 브라우저 표시 영역이 넓으면 좌우에 같은 너비의 `#303A32` 페이지 배경이 보인다. 좁으면 전체를 축소하며 필요한 위아래 여백은 같은 페이지 배경이다. 이미지 파일에 띠를 넣지 않는다.
- 기존 CSS의 viewport 단위는 제작 영역의 1%인 `--stage-vw`/`--stage-vh`를 참조한다. 화면 크기별 배치 규칙은 브라우저가 아니라 제작 영역을 기준으로 한다.
- 메인의 원래 2048×983 아트 좌표, 책과 옷장 내부 배치, 게임 플레이의 기존 16:9 내부 좌표계를 보존한다. 플레이 캔버스는 공통 영역 안에서 중앙에 배치되며 남는 내부 공간에는 기존 플레이 페이지 배경이 보인다. 이번 수정은 플레이 내부를 25:12 좌표계로 변환하는 작업이 아니다.
- 고정 버튼은 제작 영역 안에 유지한다. 브라우저 최상단 레이어로 올라가는 `dialog`에도 같은 배율을 별도로 적용한다.
- 원본 이미지, 이미지 슬롯과 파츠 설정, 애니메이션, 대사, 서버 콘텐츠, 저장 데이터는 변경하지 않는다. 개발자 로그인·편집·업로드 기능은 백업용으로 보존한다.

## 앞으로의 제작 방식

한 번에 한 장면 또는 한 기능을 요청받아 현재 코드와 게시된 콘텐츠를 확인하고 필요한 부분만 수정한다. 다른 화면에 영향이 생기면 범위를 먼저 설명한다. 이미지와 대사는 요청받은 내용으로 연결하고 기존 업로드 데이터나 저장 기록을 초기화하지 않는다. 확인한 변경을 GitHub `rebuild-v2`에 반영하고 기존 Vercel 주소의 배포 결과를 확인한다. 개발자 편집기의 신규 기능은 별도 요청이 있을 때만 만든다.

## 검증

Node 테스트는 공통 배율·비율·양쪽 여백과 포인터 좌표 복원을 확인한다. 브라우저에서는 21:9, 16:9, 16:10, 4:3과 작은 창에서 다섯 페이지의 실제 경계, 원래 내부 좌표, 버튼·설정·개발자 창, 크기 변경을 확인한다.

## 변경 파일과 영향

- 공통 비율·배율: `stage.js`, `stage.css`.
- 연결: `index.html`, `wardrobe.html`, `chapters.html`, `collection.html`, `game.html`.
- 제작 영역 기준으로 화면 단위만 전환: `style.css`, `books.css`, `wardrobe.css`, `game.css`, `settings.css`, `admin.css`, `ui-common.css`.
- 축소에 따른 측정 보정: `wardrobe.js`의 이름 높이 측정, `game.js`의 포인터 좌표와 긴 대사 표시 분량, `viewport-preview.js`의 실제 배율 표시. 이름·대사·폰트 크기 자체는 바꾸지 않았다.
- 검증·기준 문서: `tests/stage.test.cjs`, 이 문서.

테스트 기준: 3440×1440, 2520×1080, 1920×1080, 1920×1200, 1600×1200, 800×600. 다섯 화면의 비율·대칭 여백·클릭 위치·설정 및 개발자 로그인 창·창 크기 변경 검사 474개 통과. Node 테스트 65개 및 빌드 통과. 독립된 테스트 저장 공간에서 일반 플레이 저장 9개, 페이지 이동 후 이어하기 복원 5개 검사 통과. 검증용 대사와 로그인 모의 데이터는 QA 브랜치에만 있고 정식 사이트에 포함되지 않는다.

최종 대화·자막 회귀 검사 75개 통과: 긴 대사 줄바꿈, 입력 및 메뉴 충돌, 자동 진행·스킵, 위치와 배율, 테스트 저장 분리와 설정 반영을 확인했다.
